# מתי המתי״א — MATI

**מתי המתי״א** הוא יישומון אימון רפלקטיבי־מערכתי למדריכות חינוכיות במתי״א רג״ב.

המטרה היא לתמוך בתהליך עבודה שנתי שבו המדריכה מתכננת, בודקת השפעה בשטח, מבצעת רפלקציה ומתרגמת את הלמידה לתוכנית העבודה הבאה — תוך שמירה על אחריות מקצועית, גמישות, שיתוף פעולה מערכתי ועצמאות של המודרכים.

היישומון בנוי ב־**Next.js App Router + React + TypeScript** ומיועד כרגע לפיילוט.

## העיקרון המוצרי

MATI אינו טופס הערכה שהועבר למסך ואינו Dashboard למדידת מדריכות.

הוא נועד להיות **סביבת עבודה מקצועית שמלווה את המדריכה לאורך השנה**, תוך שמירה על התוכן, המדדים וה־Guard Rails שהוגדרו בתהליך המקצועי עם הנהלת מתי״א רג״ב והפיקוח.

לכן יש הפרדה מכוונת בין שתי שכבות:

- **הליבה המקצועית** — שלבים, שאלות, מדדים, תנאי מעבר ומחוון.
- **שכבת החוויה** — טיפוגרפיה, צבע, היררכיה, קצב מסך, סוגי כפתורים, שדות, מצבי מערכת והפחתת עומס קוגניטיבי.

שינויי UX אינם אמורים לשנות את ההיגיון המקצועי ללא החלטה מפורשת.

## שלושת שלבי העבודה

### 1. תכנון

מיועד לתחילת שנת העבודה.

סף המידע המינימלי כולל:

- קהל יעד / צוותי מוקד.
- לפחות מטרת SMART אחת.
- לפחות שני מדדי הצלחה.
- מסגרת זמן גסה.

בנוסף נאספים רכיבים כמו גמישות נדרשת, מעורבות מנהלים ועצמאות רצויה של המודרך.

לאחר השלמת הבסיס ניתן להפיק "מראה מקצועית" לפי חמשת ממדי הפיקוח.

### 2. הערכה מעצבת

מיועדת לאמצע שנת העבודה.

קיימים שני מסלולים:

- **מסלול ממוקד** — 5 סעיפים מרכזיים.
- **מסלול מלא** — 9 סעיפים ותמונה מערכתית רחבה יותר.

המיקוד הוא לא רק בשאלה האם התקיימה הדרכה, אלא האם נוצר שינוי אצל המודרך, בתלמידים ובמערכת, ומה ניתן ללמוד מהפער בין התכנון לבין היישום.

### 3. הערכה מסכמת

מיועדת לסוף השנה וכוללת שלוש שאלות מרכזיות:

1. ההישג המשמעותי ביותר לצוותי המוקד והמדד שמראה אותו.
2. נקודת המפנה האישית של המדריכה.
3. השינוי המרכזי שייכנס לתוכנית העבודה הבאה.

השלב כולל גם Rubric לשנה הבאה המבוסס על מדדים, גמישות, מעורבות מנהלים, תרגום מדיניות לעשייה וקיימות של השינוי.

## Guard Rails

המערכת אינה מאפשרת לדלג קדימה ללא בסיס מקצועי:

- מעבר לשלב 2 מחייב תוכנית עבודה מלאה במינימום הנדרש.
- מעבר לשלב 3 מחייב התחלה בפועל של ההערכה המעצבת.
- כישלון או פער בין יעד לתוצאה אינם מוסתרים, אלא הופכים לנקודת רפלקציה והחלטה.

## חמשת ממדי המראה המקצועית

1. **רפלקציה ולמידה** — בקרה עצמית, גמישות ושינוי בעקבות תובנות.
2. **מדדים כמותיים** — צוותי מוקד, הוכחת שיפור ואיכות המדידה.
3. **לוח זמנים ויישום** — אחוז מימוש, עקביות וזיהוי חסמים.
4. **מערכת ואחריות** — מנהלים, משאבים וחלוקת אחריות.
5. **אופרטיביות ועצמאות** — יכולת המודרך לפעול באופן עצמאי ועקבי.

## כיוון UX/UI

העיצוב מותאם לסביבת העבודה של מדריכות מתי״א רג״ב ולא לשפה של מוצר SaaS גנרי.

עקרונות העבודה הנוכחיים:

- עברית RTL מלאה.
- **Heebo** כגופן ממשק מרכזי.
- היררכיה חזותית ברורה בין פעולה, מידע וסטטוס.
- כחול חינוכי כצבע פעולה מרכזי; טורקיז וזהב כצבעי עזר וחיווי.
- פחות קישוטי Dashboard ויותר תחושה של סביבת עבודה מקצועית פנימית.
- שדות עם Labels גלויים, Focus ברור ואזורי לחיצה נוחים.
- שאלונים ארוכים מוצגים כרצף אנכי כדי להפחית זיגזג ועומס סריקה.
- חלוקת תוכנית העבודה לקבוצות חשיבה במקום הצגת כל השדות כבלוק אחד.
- שימוש בצבע רק כאשר הוא מסייע להבין פעולה, מצב או משמעות.
- התאמה למסכים קטנים ולשימוש במהלך יום עבודה עמוס.

המטרה אינה להעתיק את אתר מתי״א רג״ב, אלא לגרום ליישומון להרגיש כמו כלי ששייך לאותה מערכת מקצועית.

## פרטיות וזיכרון

בגרסת הפיילוט הנוכחית:

- אין Backend.
- אין מסד נתונים חיצוני.
- אין שליחת תוכן רפלקטיבי לשרת.
- מצב המשתמשת נשמר ב־`localStorage` בדפדפן המקומי.

משמעות הדבר היא שהמידע נשמר רק באותו דפדפן ובאותו מכשיר, ויימחק אם המשתמשת מוחקת את אחסון האתר.

## ארכיטקטורה

```text
app/
├── layout.tsx      # RTL, metadata, typography
├── page.tsx        # flow, forms and interaction
└── globals.css     # design system and responsive UI

lib/
└── stages.ts       # stage detection, guard rails, state and scoring
```

החלטה ארכיטקטונית מרכזית: **הלוגיקה המקצועית נשמרת מחוץ לרכיבי התצוגה ככל האפשר**, כדי שאפשר יהיה לשנות UI בלי לשנות בטעות את כללי המוצר.

## Stack
